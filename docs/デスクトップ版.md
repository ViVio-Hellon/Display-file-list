# デスクトップ版(Tauri)の作り

VER2.0.0 から、ブラウザで開く代わりに**専用の窓(`ファイル名一覧取得.exe`)**で動かせるようになりました。
**ポートを使いません。** ブラウザ版(`Start.vbs` / `start.bat`)もそのまま残してあり、予備として使えます
(ただし**同時には動きません**。下の「ブラウザ版とのすみ分け」)。

作りは、移行済みの `ViVio-Hellon/python-web-tools`(VER4.0.0〜)と、同じ作りを写した
`ViVio-Hellon/coil-packing-tools`(統合 1.1.0〜)に合わせました。

## 何が何をするか(各言語が得意なことをする)

```
ファイル名一覧取得.exe(Rust / Tauri)        … src-tauri/
 ├─ 窓(WebView2)・2つ目の起動の防止(OS のファイルロック)・終了
 ├─ CSS・JS を直接返す(Python を通さない)
 ├─ Python を子として起動・見張る(落ちたら理由の画面)
 └─ 画面の要求(app://…)を受けて、Python の標準入力へ渡す
        │ 標準入出力(1件 = 見出し1行 + 本文)
        ▼
bridge.py(Python・標準ライブラリだけ)        … ポート無しの入口
 └─ App.handle(要求) を呼ぶだけ(ブラウザ版の server.py と同じ渡し方。待ち受けない)
        ▼
app/(Python)                                  … 一覧・Val・全角→半角・リネーム・ログ・画面の組み立て(変わらず)
app/static/js(JS)                             … 画面の操作(変わらず。デスクトップ版のための手直しは無い)
```

| 担当 | 理由 |
|---|---|
| **Rust**: 窓・起動・終了・2つ目の起動の防止・Python の見張り・静的ファイル | OS の窓・プロセス・ファイルロックを扱うのが得意。exe 1つで配れる。静的ファイルは Python を通さないぶん速い |
| **Python**: 一覧・並べ替え・リネーム・ログ・画面の組み立て | 重い処理が無い(フォルダを読むだけ)。VBA と同じ結果を守る試験(VBA の `Val`・先頭 300 件・`_` の分け方など)がこの形で書かれている。書き直す利点が無く、危険だけがある |
| **JS**: 画面の操作・コピー・印刷の紙面 | 今までどおり |

python-web-tools / coil-packing-tools は Flask を WSGI として呼ぶが、このツールは初めから**標準ライブラリだけ**
(`http.server` と自前の経路表 `app/web.py`)で作ってあるので、`App.handle` をそのまま呼ぶ。
**デスクトップ版でも Python に追加の部品は要らない**(ラインPCの制約のまま)。

## ポートを使わない仕組み

- 画面は独自の宛先 `app://localhost/`(Windows の WebView2 では `http://app.localhost/`)を読む。
  これは**ネットワークを通らない**(外枠の中で受ける名前)
- 外枠はその要求を Python の標準入力へ渡し、標準出力から応答を受け取る(`src-tauri/src/bridge.rs` と `bridge.py`)
- CSS・JS は、Python が起動時に知らせる置き場所(`app/static`)から外枠が直接返す
- 起動トークン・Host の確認・同一オリジンの確認など、アプリ側の守りはそのまま生きている
  (Host は `app.localhost` / `localhost` だけ受ける。待ち受けの宛先 `127.0.0.1:ポート` は受けない)
- 試験で確かめていること:
  - `tests/test_bridge.py`: **ソケットを開くと落ちる**ようにして Python を起動しても、画面・一覧・終了が通る
  - `scripts/desktop_smoke.py`: exe を本当に起動し、exe・Python・WebView の**どのプロセスもポートで待ち受けていない**
    (GitHub Actions の Windows でも流す)

## 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓がすぐ出て「起動しています」→ 業務画面(ブラウザ版の待機画面は通らない) |
| もう1つ起動しようとした | 新しく起動せず、開いている窓を前に出す(OS のファイルロック `runtime\desktop.lock` でも止める) |
| 窓の × / 画面の「終了」 | どちらも画面の「終了」と同じ道(`/api/shutdown`)。**リネームの途中なら閉じずに理由を出す**(ブラウザ版と同じ) |
| 画面を閉じたら約 90 秒で終わる | ブラウザ版だけ。デスクトップ版は窓を閉じれば exe も Python も終わる |
| 一覧をコピー | ブラウザ版と同じ(Excel 用の表とタブ区切りの2つ) |
| 一覧を印刷 | ブラウザ版と同じ紙面。印刷の窓は WebView2 のもの(Edge と同じ部品) |
| ログの面・CSV | ブラウザ版と同じ(CSV は出力先の「書き出し」へ。ダウンロードはしない) |
| Python が見つからない・起動できない | 理由と次にすること(Python の入れ方)・ログの場所を窓に出す |
| Python が途中で落ちた | 窓を読み直して理由の画面を出す |
| exe を止めた | 標準入力が閉じるので Python も終わる(取り残さない) |
| stop.bat | デスクトップ版の窓にも「閉じて」と頼む(窓の × と同じ)。リネームの途中なら閉じない(戻り値 2)。`--force` で窓ごと止める |

Python は**同梱しません**。各PCに入っている Python を使います(`python.exe` → `py.exe -3` の順に探す。
`FILELIST_TOOL_PYTHON` で指定もできる)。**追加の部品は要りません**(ブラウザ版と同じ)。
Python はコンソールの窓を出さずに起動します。`-X utf8`(UTF-8 モード)では起動しません(ブラウザ版と同じ文字コードの動き。
外枠とのやりとりだけ `PYTHONIOENCODING=utf-8`)。

## 印刷(ブラウザ版との違い)

| | ブラウザ版(Edge のタブ) | デスクトップ版(窓) |
|---|---|---|
| 印刷の窓・描き方 | Edge の印刷プレビュー | 同じもの(WebView2 は Edge と同じ部品。`window.print()` をそのまま受ける) |
| **印刷の設定の置き場所** | Edge の設定 | **窓が自分で持つ**(Edge で選んだ「余白なし」などは引き継がない) |

紙面は `@page` で**A4 縦・余白0**を決め、紙の端からの距離は紙面の中で取り(8mm)、色は背景のグラフィックの
有無に関わらず刷る(VER1.6.1)ので、**印刷の設定が既定でも同じ紙面になる**。

## ブラウザ版とのすみ分け(どちらを後から開いても止まる)

ブラウザ版とデスクトップ版は**同じ手元の設定・ログ・最後に使ったパス**を使うので、同時には動かしません。

| 動いているもの | 後から開いたもの | 動き |
|---|---|---|
| ブラウザ版 | デスクトップ版 | 窓に「ブラウザ版のファイル名一覧取得が動いています」と出して使わせない(ブラウザの「終了」か stop.bat で止めてから) |
| デスクトップ版 | ブラウザ版(Start.vbs / start.bat) | 「デスクトップ版のファイル名一覧取得が動いています」と出して起動しない |
| デスクトップ版 | デスクトップ版 | 起動せず、開いている窓を前に出す |

- デスクトップ版は動いているあいだ、`%LOCALAPPDATA%\FileListTool\runtime\desktop.lock` を握り(OS のロック。落ちれば外れる)、
  `desktop.json`(Python の番号・起動時刻・窓の番号)を置く。ブラウザ版の起動と stop.bat は `desktop.json` を見る
- `desktop.json` が残っていても、番号と起動時刻で本人か確かめる(PC の再起動で番号が使い回されても取り違えない。VER1.7.1 と同じ考え)
- 判断は短い門(`runtime\startup.gate`。OS のロック)の中でするので、ほぼ同時に両方を起動しても2つとも動き出すことはない

## 作り方

**Windows 版は GitHub Actions が作ります**(`.github/workflows/desktop-windows.yml`「デスクトップ版(Windows)」)。
push するたびに、Python の試験・Rust の試験・exe の作成・exe を起動しての確認まで流れ、
成果物 `FileListTool-windows` に `FileListTool.exe` が入ります(Actions の画面の「Run workflow」からも流せます)。

配るとき:

1. 成果物から `FileListTool.exe` を取ってきて、ツールのフォルダの**直下**(Start.vbs と同じ所)に置く
2. `python scripts\make_dist.py` を流す(`dist\ファイル名一覧取得\` に、`ファイル名一覧取得.exe` の名前で入る)。
   外枠のソース(`src-tauri`)・試験・`.github`・移植元の VBA は配らない

手元で作るとき(開発機):

```
cd src-tauri
cargo test                       # Rust の試験
cargo build --release            # target/release/FileListTool(.exe)
python ../scripts/desktop_smoke.py --exe target/release/FileListTool     # Linux は xvfb-run -a を前に付ける
python ../tools/desktop_e2e.py --exe target/debug/FileListTool           # 窓の通し試験(Linux)
```

Linux で作るには WebKitGTK が要ります(`libwebkit2gtk-4.1-dev` など)。窓の通し試験には
Xvfb・xdotool・WebKitWebDriver(`webkit2gtk-driver`)・tauri-driver(`cargo install tauri-driver`)も要ります
(現場の PC には要りません)。

## 置き場所の決まり

- exe は `bridge.py` と同じフォルダに置く(上の階層もたどるので、`src-tauri/target/...` から動かしても見つかる)。
  `FILELIST_TOOL_ROOT` で指定もできる
- 版は `config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の3か所。食い違うと試験が落ちる
- アイコンは `scripts/make_desktop_icon.py` で作る(標準ライブラリだけ。`src-tauri/icons/`)
- ツールのフォルダに `__pycache__` を作らない(Python のキャッシュはローカル領域の `pycache`)

## 確かめたこと(開発機の Linux・WebKitGTK の窓)

`tools/desktop_e2e.py`(窓を WebDriver で操作。13項目すべて OK):

- 窓に業務画面が出る・CSS / JS は外枠(Rust)が返している
- ファイルの一覧(VBA どおりの並び)・一覧をコピー・一覧を印刷(紙面ができて印刷が呼ばれる)
- 選択ボタンで「フォルダ名取得」に変わる・フォルダの一覧
- 全角→半角(下見 → 実行で、ディスクの名前が本当に変わる)
- 「ログ」の画面へ移って戻れる
- 画面の「終了」・窓の ×(ウィンドウマネージャと同じ合図)で exe も Python も終わる
- ブラウザ版が動いているときは窓に理由が出る

`scripts/desktop_smoke.py`(WebDriver なし。15項目すべて OK):

- 起動から Python が受け付けるまで約 0.6 秒・画面が Python から届く
- **どのプロセスもポートで待ち受けない**
- 2つ目の exe は起動せずに終わる(1つ目はそのまま)
- デスクトップ版が動いているとブラウザ版は起動しない / ブラウザ版が動いているとデスクトップ版は断る
- stop.bat でデスクトップ版を閉じる(exe も Python も居なくなり、印も消える)

## 確かめきれていないこと(Windows の実機で見る)

GitHub Actions の Windows で「試験・起動して画面が届く・待ち受けない・2つ目の起動・すみ分け・stop.bat で閉じる」までは
自動で分かります。次は**実機で人が見る**必要があります:

- 一覧を印刷から実際に紙が出ること(WebView2 の印刷の窓)。紙の端から 8mm 内側に収まること
- 一覧をコピーして Excel に貼ると列に分かれ、`6-1` が日付にならないこと
- 2つ目の起動で、開いている窓が前に出ること
- リネームの途中に窓の × を押すと、理由が出て閉じないこと(Linux では処理を長引かせられず、通しでは見ていない。
  断る仕組みそのものは試験で確かめている)
- **Microsoft Store の Python の PC で**起動できること
